# Mamaearth Returns & Growth Intelligence Pipeline

## Project Overview

This project builds an end-to-end data analytics pipeline to identify where product returns are affecting revenue quality and margins.

The pipeline contains three connected layers:

1. SQL relational storage and reporting
2. Python data cleaning, exploratory data analysis (EDA), and visualization
3. GenAI-powered business insight narration using Gemini

The SQL layer reports on the raw source data. The Python layer independently cleans and analyzes the original CSV files. The verified findings generated by Python are then passed to the GenAI narrator to produce a business-focused Situation-Complication-Resolution (SCR) narrative.

# 1. SQL Relational Layer

The SQL layer creates the relational database, loads the source data, and produces the required business reports.

This project was tested using MySQL.

Before running the SQL scripts, create and select a database in MySQL:

```sql
CREATE DATABASE IF NOT EXISTS mamaearth_returns;
USE mamaearth_returns;
```

Run the following `SOURCE` commands from the MySQL command-line client, with your terminal working directory set to the project root.

## Step 1: Create the Database Tables

From the MySQL command-line client, run the following command from your project root directory:

```sql
SOURCE sql/schema.sql;
```

This creates the following tables:

- `customers`
- `products`
- `orders`

## Step 2: Load the Seed Data

After creating the tables, load the CSV-derived records by running:

```sql
SOURCE sql/seed_data.sql;
```

Verify that the data has been loaded correctly:

```sql
SELECT COUNT(*) FROM customers;
SELECT COUNT(*) FROM products;
SELECT COUNT(*) FROM orders;
```

Expected row counts:

| Table     | Expected Rows |
| --------- | ------------: |
| customers |            45 |
| products  |            16 |
| orders    |           180 |

## Step 3: Run the SQL Reports

After loading the seed data, execute the report queries:

```sql
SOURCE sql/reports.sql;
```

The SQL reports cover:

- Total orders, total revenue, and average order value
- Missing ratings and customers with no orders
- Return rates by city
- Customer spending rankings
- Revenue by product category
- Customer name pattern matching
- Distinct acquisition sources
- Customer loyalty tiers

These reports use the raw data before the cleaning and analysis performed by Python.

# 2. Python Cleaning and EDA Layer

The Python analysis uses the original CSV files directly from the `data/` folder. It runs independently of the SQL database.

### Python Dependencies

Install the packages required for data cleaning, analysis, and visualization from the project root directory:

```bash
python3 -m pip install pandas numpy matplotlib
```

To use the online Gemini API, also install the Google GenAI SDK:

```bash
python3 -m pip install google-genai
```

The offline narrator uses a deterministic template and does not require a Gemini API key or network access. The Gemini SDK is required only for the online generation path.

Run the script from the project root:

```bash
python3 analysis/clean_and_eda.py
```

The script performs the following tasks:

- Loads and inspects the source data
- Standardizes payment-method values
- Detects and removes duplicate orders
- Handles missing values
- Merges orders with customer and product information
- Calculates order values and reconciles revenue
- Detects quantity outliers using the IQR method
- Tests the COD return-rate hypothesis
- Segments return rates by payment method and city tier
- Examines correlations between selected variables
- Compares monthly revenue before and after outlier correction

At the end of the analysis, the script generates:

```text
narrator/findings.json
```

Task 5 of Part 2, implemented at the end of `analysis/clean_and_eda.py`, generates `narrator/findings.json` from the calculated results.

This JSON file contains verified findings calculated by the Python analysis. It supplies the input for the GenAI narrator, keeping the reported figures connected to the analysis results.

# 3. Visualization Layer

After running the cleaning and EDA script, run the visualization script from the project root:

```bash
python3 analysis/visualize.py
```

The script generates two visualizations in the `visualizations/` folder:

- `return_rate_by_payment.png` — a bar chart comparing return rates by payment method, with percentage labels and a title highlighting the high COD return rate.
- `monthly_revenue_trend.png` — a line chart showing outlier-corrected monthly revenue and identifying the true peak month.

The scripts can be rerun using the original CSV files to regenerate the analysis outputs and charts.

# 4. GenAI-Powered Insight Narrator

The narrator converts the verified findings into a business narrative using the Situation-Complication-Resolution (SCR) structure.

The input file is:

```text
narrator/findings.json
```

The narrator script is:

```text
narrator/generate_narrative.py
```

The script uses Google's GenAI SDK to generate a business-focused narrative from the verified findings.

Google AI Studio provides a free Gemini API key with a free usage tier for learning and practice. The project also includes an offline fallback, allowing the narrator to run without an API key, network access, or API spending.

## Option A: Run with Gemini API

Set your Gemini API key as an environment variable in the terminal:

```bash
export GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
```

Replace `YOUR_GEMINI_API_KEY` with your own key. Never hardcode the actual key in the Python source code or commit it to GitHub.

Verify that the environment variable is configured without displaying the key:

```bash
python3 -c "import os; print('API key configured:', bool(os.getenv('GEMINI_API_KEY')))"
```

Then run the narrator:

```bash
python3 narrator/generate_narrative.py
```

When the API call succeeds, Gemini generates the SCR narrative using the verified findings. If the API call fails, the program automatically switches to the offline fallback.

## Option B: Run Without an API Key

The narrator includes a deterministic offline fallback that generates a business narrative using the verified findings in `narrator/findings.json`.

Run the following command from the project root without configuring `GEMINI_API_KEY`:

```bash
python3 narrator/generate_narrative.py
```

When no API key is configured, the program automatically selects the offline fallback. It also switches to the fallback if a Gemini API request fails.

The offline path requires:

- No Gemini API key
- No network access
- No API spending
- No Gemini SDK installation, provided the SDK imports are kept inside the online generation function

The generated narrative follows the Situation–Complication–Resolution (SCR) structure and uses values from `findings.json`.

# 8. Key Verified Findings

The cleaned analysis produces the following verified findings:

- **Cleaned total revenue:** ₹97,358.30
- **Raw SQL revenue:** ₹99,860.20
- **Duplicate reconciliation difference:** ₹2,501.90
- **COD return rate:** 44.4%
- **Highest-risk segment:** COD + Tier-2, with a 54.5% return rate
- **True revenue peak:** March 2026, with revenue of ₹20,318.90
- **January apparent revenue:** ₹29,582.10
- **January corrected revenue:** ₹11,637.10

January's apparent revenue lead was inflated by two bulk quantity outlier orders. After excluding those outliers from the monthly revenue analysis, March 2026 is the genuine peak month.

# 9. Reproducibility

The original CSV files in the `data/` folder are kept unchanged. All data cleaning, duplicate removal, missing-value handling, outlier detection, and analysis are performed programmatically in Python.

The `analysis/clean_and_eda.py` script generates `narrator/findings.json` from the calculated results. The narrator consumes this file to produce a business narrative without manually re-entering the verified figures.

To reproduce the complete pipeline, follow the execution order described in this README: run the SQL scripts, execute the Python cleaning and EDA script, generate the visualizations, and run the GenAI narrator with a Gemini API key or its offline fallback.
